# Rise LinkedIn post

Create a professional contribution for people who make product, software and
operational decisions. The post must contain a Rise perspective, not a polished
summary that could come from any company.

## Inputs

Read the approved brief, `brand/voice.sk.json`, claim evidence and prior LinkedIn
openings. Use only public evidence. Identify one audience, one decision and one
useful implication before drafting.

## Copy sequence

1. Open with a concrete observation, trade-off or decision.
2. Add one grounded example, constraint or verified fact with its claim ID.
3. Explain what it changes for software, product or operations.
4. Close with a useful next step only when one exists.

Prefer natural paragraphs and varied sentence length. Use `my` only for work Rise
can prove. Never fabricate a client outcome, personal experience or team quote.
Do not start with a generic question. Avoid theatre such as a one-sentence line
break after every sentence.

## LinkedIn contract

- Maximum 3,000 characters; aim for the shortest complete explanation.
- Use 0–3 controlled hashtags. Hashtags are optional, not a footer template.
- Add a direct HTTPS link only when visiting the source or product is the objective.
- Mention a person or Page only with a confirmed handle and real relevance.
- For a document carousel, use 4–8 flattened PDF pages of one size and a clear,
  factual document title.
- A repost or external article needs at least one or two sentences of Rise's own
  point of view.

Before approval, name the unique perspective in one sentence. If that sentence is
missing, revise the post.

## Human review

Read the caption aloud. Replace abstract nouns with the actual action, decision,
constraint or consequence. Remove any sentence that only announces, praises or
recaps. Confirm that a competent Rise colleague could defend every sentence.

## Output contract

Return a B2B consideration caption, one named Rise perspective, claim IDs, optional direct HTTPS
link only for a visit goal, 0–3 hashtags and a 4–8 page flattened PDF brief when using a document.

## Stop conditions

Stop on generic AI polish, repetitive templates, unsupported expertise, engagement
bait, automated comments, an unverified mention, a claim without evidence, or a PDF
that was not visually inspected.

## Pressure test

Good: a trade-off from a public case study names the operational consequence. Bad: a generic
summary with a sales link but no Rise position is not a LinkedIn post.
